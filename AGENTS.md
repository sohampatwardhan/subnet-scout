# Agent notes

Subnet Scout uses Kiro-style spec-driven development. Specs are the source of behavior. Code follows them.

## Clean-room rule

This is a clean-room implementation of a local IPv4 scanner.

- Do not copy or translate source, tests, resources, icons, marketing text, or port-preset files from Angry IP Scanner or from any other IP scanner.
- Do not depend on a GPL scanner.
- Do not use the word Angry in the product name, bundle id, or icon.
- Do not commit MCP client configuration, including an Iconify server entry. The interface uses SF Symbols. The app icon is generated by `scripts/generate-app-icon.py`.
- Do not rename `sohampatwardhan/subnet-scout` from an implementation task. The working title is recorded in `.kiro/specs/local-network-scan/requirements.md`, along with why it is unsafe to ship and three alternatives.

Load `.kiro/steering/clean-room.md` with `#clean-room` when a change touches scanning or branding.

## Workflow

The skills that define the file shapes are [kiro-sdd-skills](https://github.com/sohampatwardhan/kiro-sdd-skills).

1. Pick one workflow and keep it for that spec folder: Requirements-First, Design-First, Quick Spec, or Bugfix.
2. Write `.kiro/specs/<feature>/requirements.md` (or `bugfix.md`), then `design.md`, then `tasks.md`, unless the user asked for a different order.
3. Acceptance criteria use EARS (`WHEN` / `IF` / `WHILE` / `WHERE` … `THEN the system SHALL`).
4. Every criterion id appears in a task `_Requirements:_` line. The task graph in `tasks.md` is a Mermaid flowchart with ELK layout, nested phase and parallel subgraphs, and `classDef` styles.
5. Flowcharts and state diagrams set `config.layout` to `elk`.
6. On a gated workflow, stop after each file for approval. Quick Spec skips those stops only when the user asked for one pass.
7. Implementing a task means doing that numbered task, including its tests, and checking the box only after the work is in the tree.

v0.1 was written as a Quick Spec because the initial request asked for the spec and the implementation together. Later features get their own folder. Do not renumber requirement or task ids that are already cited. Append new numbers.

Optional tasks 8 (IPv6), 9 (macOS MAC address), and 10 (scan history) are not part of a required run.

## Layout

`ScannerCore` is the Swift package. It must not import SwiftUI. Apple-only calls sit behind `TCPConnectProbing`, `ICMPEchoProbing`, and `HostNameResolving`. The app is `App/SubnetScout`, generated from `App/project.yml`. Do not commit the generated Xcode project.

Public ScannerCore declarations use DocC comments with `- Parameters`, `- Returns`, and `- Throws` when those apply.
